# 採用版(重複句チェックの表の一本化だけ)の検証

対象は `patches/adopted-walk-table.diff`(`f428588` に当てる 1 コミット分、コミット文は
`patches/adopted-walk-table-commit-message.txt`)。

採否の決定(ユーザー判断):

| 施策 | 決定 | 理由 |
|---|---|---|
| 重複句チェックの表の一本化 | 採用 | 全文に効き、確保は変わらず、レビューでデグレが一度も出ていない |
| 暗黙バインドと容量の事前確保 | 不採用 | デグレが 3 件出た部分で、短縮は 1 文あたり 0.1〜0.5 µs。記録は `results/declined-reservation.md` |
| 128 個以上でのハッシュ索引 | 不採用 | 128 個以上のパラメータを持つ文は稀。記録は `results/panel-audit.md` |

計測値はクラウドコンテナ(.NET 10)上の相対値。確保バイト数は毎回同じ値になる。

## 1. 中身

変更は `SqlBuilderBase.cs`(+168 / −46 行)とテスト 2 ファイル(+105 行)。差分全体は
3 ファイル、+273 / −46 行。`SqlBuildingBuffer`、`BindValue`、`IN` / `VALUES` の各句、CHANGELOG には
触れない。

- 厳密な型をキーにした表 1 つ(`TraitsByType`)から、句の役割と 2 種類の種別を 1 回で引く。
  現行は `FrozenDictionary` を 2 回引き、型判定を 30 回ほど行っていた。
- 排他ペアは種別ごとのビットマスクで判定する。違反を見つけたあとのメッセージ組み立ては
  元の表(`ExclusiveKinds` / `ExclusiveBranchKinds`)を表の順に読むので、文言は現行と同じ。
- 型判定が基底クラス越しに拾っていた `RequirementOnlyOnClause` は表に並べて載せた。
  表に載っていない派生クラスや、`ISelectItemsClause` / `IJoinedRelation` の実装が増えると
  `DuplicateClauseWalkTests` が落ちる。

## 2. ゲート

- `dotnet build SqlArtisan.sln -c Release`: エラー 0(警告 20 は現行と同じ)。
- 単体テスト 2,267 / 2,267、`SqlArtisan.Analyzers.Tests` 2,166 / 2,166、
  `SqlArtisan.TableClassGen.Tests` 336 / 336、`dotnet format --verify-no-changes` 終了コード 0。
- 結合テストの DB 不要スライス 69 / 69、SQLite 501 / 501。
- 現行との出力一致: `H.dll probe`、`stress`(5 方言 20,000 文 × 並列 3 周、ダイジェスト一致)、
  `mergemsg`、`outloop 130 600`。
- 変異テスト 11 本: ブロックと分岐それぞれの「重複の判定を外す」「排他の判定を外す」「見た種別を
  記録しない」、JOIN 条件の重複と欠落の判定を外す、`InsertIgnoreIntoClause` の役割を落とす、
  MERGE 分岐の排他ペアを逆順に読む、の 10 本はテストが落ちる。ブロックの排他ペアを逆順に読む 1 本は
  通るが、ブロックの種別は排他の相手が 1 つずつしかないのでメッセージは変わらない(等価な変異)。
- 追加したテスト: `DuplicateClauseWalkTests`(表の網羅)、`BuilderReuseTests` の 2 件
  (保持した INSERT IGNORE ステージ、排他の相手が 2 つある MERGE 分岐で名指しされるペア)。

## 4. 取り込み時に必要なこと

- CHANGELOG の未リリース項目「`Build()` finds each clause's kind with one lookup … about 15% faster」は
  #845 の変更を表しており、文章はこの変更後も正しい。数字だけが #845 時点のもので、この変更で
  さらに速くなる。基準機で公式ベンチマークを測り直して同じ項目の数字を差し替える(測らないなら
  数字を消す)。README のベンチマーク表も同じ。パッチはどちらも変えていない。
- コンテナを使う結合テスト(MySQL、Oracle、PostgreSQL、SQL Server)を CI で通す。
