# 採用版(索引なし)の再検証

対象は `patches/adopted-walk-table-and-reservation.diff`(`f428588` に当てる 1 コミット分、
コミット文は `patches/adopted-commit-message.txt`)。`patches/final-walk-table-and-parameter-index.diff`
から、128 個以上で切り替わるハッシュ索引(`IndexedParameterList`)だけを外したもの。
128 個以上のパラメータを持つ文は稀、という判断による。

計測値はクラウドコンテナ(.NET 10)上の相対値。確保バイト数は毎回同じ値になる。

## 1. 中身

| 対象 | 変更 |
|---|---|
| 重複句チェック(`SqlBuilderBase`) | 索引あり版と同じ。厳密な型をキーにした表 1 つから役割と種別を 1 回で引く |
| 暗黙バインド | 索引あり版と同じ。内部クラス `ImplicitBindValue`、`IN` / `NOT IN` / `VALUES` の容量の事前確保 |
| パラメータの重複検出 | 現行どおりの線形走査(リストをスパンとして走査する形にしただけ)。索引、借り物の配列、分散登録、出力パラメータの特別扱いはない |

差分は 12 ファイル、+677 / −59 行(索引あり版は +1,031 / −67 行)。うちテストが約 400 行。

## 2. ゲート

- `dotnet build SqlArtisan.sln -c Release`: エラー 0(警告 20 は現行と同じ)。
- 単体テスト 2,282 / 2,282、`SqlArtisan.Analyzers.Tests` 2,166 / 2,166、
  `SqlArtisan.TableClassGen.Tests` 336 / 336、`dotnet format --verify-no-changes` 終了コード 0。
- 結合テストの DB 不要スライス 69 / 69、SQLite 501 / 501。
- 現行との出力一致: `H.dll probe`、`stress`(ダイジェスト一致)、`mergemsg`、`outloop`(32/223、
  130/600、130/2000)、`fuzz 3000 1500`(225 万ステップ、ダイジェスト一致)。
- 変異テスト 10 本: `VALUES` / `NOT IN` / `IN` の確保を外す、すべての `BindValue` を数える、先頭既出の
  判定を外す、確保を 2 倍にする、走査が何も見つけない、`InsertIgnoreIntoClause` の役割を落とす、
  MERGE の排他ペアを逆順に読む、の 9 本はテストが落ちる。容量の判定を外す 1 本は通るが、索引が
  ないこの版では SQL も確保も変わらず時間だけが変わる(等価な変異)。判定順の理由は該当箇所の
  コメントに書いてある。
- 索引専用のテストは削除した。`NOT IN` と `VALUES` の確保は索引の型を見るテストで守られていたので、
  確保バイト数の差を比べるテストを `IN` / `NOT IN` / `VALUES` の 3 形に広げて置き換えた。

  約 0.8〜1 ms、10,000 個で 20 ms 前後(現行は約 30 ms)。

## 4. 確かめていないこと

- 索引を外したあとの状態に対する、独立した席のレビュー。確認は上のゲート、変異テスト、出力比較。
  残したコードは索引あり版で 2 回の最終確認を通ったものと同じで、変えたのは索引の削除とテストの
  入れ替えだけ。
- コンテナを使う結合テスト(MySQL、Oracle、PostgreSQL、SQL Server)。Docker がない。
- 基準機での公式 BenchmarkDotNet。CHANGELOG の未リリース項目「約 15% 速い」と README の表は
  測り直して差し替える必要がある(このパッチは数字を変えていない)。
- .NET 8 ランタイムでの時間、1,000 個を超えるパラメータでの実測。
